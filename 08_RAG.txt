# Introduction to RAG
RAG stands for "RETRIEVAL AUGMENTED GENERATION".
RAG is a a technique that combines information retrieval with language generation where a model retrieves relevant documents from a knowledge base and then uses them as context to generate accurate and grounded responses.
Benefits of using RAG:
    (i) Use of up-to-date information
    (ii) Better privacy (RAG can help organizations use private data without exposing it publicly, but security depends on how the complete RAG system is designed and deployed.)
    (iii) No limit of document size

- Why RAG?

If you use ChatGPT, there are certain things it may not be able to do accurately without access to external or private information. For example:

(i) Latest Current Affairs
If you ask ChatGPT about very recent events, such as information from the past one or two days, it may not provide an accurate or up-to-date response.

This is because an LLM is trained on a specific collection of data and may not have access to the latest information.

(ii) Personal Data
If you ask an LLM to read your personal Gmail messages, it will not be able to do so unless you provide access to those messages through an appropriate integration.
Similarly, if you ask questions about a company's private or confidential data, the LLM cannot answer accurately unless that information is provided to it.

RAG helps address these limitations by retrieving relevant information from external sources or private documents and providing it to the LLM as context.

# Document loaders
There are 100s of document loaders in langchain, but we will study the 4 important ones.
(i) TextLoader
(ii) PyPDFLoader
(iii) WebBaseLoader
(iv) CSVLoader

Document loaders are components in LangChain used to load data from various sources into a standardized format (usually as Document objects), which can then be used for chunking, embedding, retrieval, and generation.

For every document, we have two things: page_content and meta_data.
Document(
    page_content = "The actual text content",
    metadata = {
        "source" : "filename.pdf",
        ...
    }
)


- Why do we need Document Loaders?
An LLM cannot automatically read every file on your computer.
For example, if you have a PDF containing company policies, you first need to:
Read the PDF.
Extract its text.
Convert that text into a usable format.
Pass it to the next RAG component.

The Document Loader performs the first part of this process.

- What is a Document?
After loading, LangChain usually represents the extracted information using a Document object.
A Document mainly contains two things:
    Document(
        page_content="The actual text...",
        metadata={"source": "company_policy.pdf"}
    )

page_content -> Contains the actual extracted text.

metadata -> Contains additional information about the text, such as:
    File name
    Page number
    Source
    Document type

# TextLoader

## Definition

TextLoader (works only with .txt files) is a simple and commonly used document loader in LangChain that reads plain text (.txt) files and converts them into LangChain document objects.

## Working of TextLoader

Text File
    ↓
TextLoader
    ↓
load()
    ↓
Document Object
    ├── page_content
    └── metadata

## Code

from langchain_community.document_loaders import TextLoader

loader = TextLoader(r'file_path', encoding='utf-8')
docs = loader.load()

print(docs)  # It prints a list of documents.

print(docs[0].page_content)

print(docs[0].metadata)

## Using the Loaded Text with an LLM

We can pass the loaded text into the LLM. For example, we can give a prompt:

"Write a short summary on the following document."


# PyPDFLoader (Doesn't work well on scanned data)

PyPDFLoader is a document loader in LangChain used to load content from PDF files and convert each page into a document object.

## Structure

[
    Document(
        page_content="Text from page1...",
        metadata={
            "page": 0,
            "source": "filepath"
        }
    ),
    Document(
        page_content="Text from page2...",
        metadata={
            "page": 1,
            "source": "filepath"
        }
    ),
    ...
]

## Working

PDF File
    ↓
PyPDFLoader
    ↓
documents = [
    Document(page_content="Page1...", ...),
    Document(page_content="Page2...", ...)
]

## Code

from langchain_community.document_loaders import PyPDFLoader

loader = PyPDFLoader(r'filename')
docs = loader.load()

print(len(docs))  # len = Number of pages
print(docs[0].page_content)  # Print 1st page
print(docs[1].page_content)  # Print 2nd page

## Limitations

1. It mainly extracts text, not the complete visual layout.
2. It may not read scanned-based PDFs properly.
3. Tables cannot be read properly.

## Other PDF Loaders

| Use Case | Recommended Loader |
|---|---|
| Simple, clean PDFs | PyPDFLoader |
| PDFs with tables/columns | PDFPlumberLoader |
| Scanned/image PDFs | UnstructuredPDFLoader |
| Need layout and image data | PyMuPDFLoader |
| Want the best structure extraction | UnstructuredPDFLoader |
