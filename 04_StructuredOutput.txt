# Structured Output
The prompt that we give to the LLM was in TEXT format and what LLM gives it is also in TEXT format, but most probably in unstructured form

In LangChain, structured output refers to the practice of having language model return responses in a well-defined data format (for example, JSON), rather than free-form text. This makes the model output easier to parse and work with programmatically.

For example:
[Prompt] - Can you create a one-day travel time table for Paris?
[LLM's unstructured Response]
Here's a suggested time table: Morning : Visit the Eiffel tower
Afternoon: Walk through the Louvre Museum
Evening: Enjoy dinner at a Seine riverside cafe
[JSON enforced output]
[
    {"time": "Morning", "activity": "Visit the Eiffel Tower"},
    {"time": "Afternoon", "activity": "Walk through the Louvre Museum"},
    {"time": "Evening", "activity": "Enjoy dinner at a Seine riverside café"}
]

- Why do we need Structured Output
(i) Data Extraction
    Suppose if we are making Naukri.com website. What key values we can extract from the data would be:
        Name
        10th Marks
        12th Marks
        College
        etc
    And than we can also insert the data into the database easily
(ii) API building
(iii) Agents
    For working with Agents we required Structured Output
    LLM generates the data, while structured output gives that data a predictable format so the agent/application can reliably process and use it.

    1. LLM generates the information

    "What city does the user want?"
            ↓
          Delhi

    2. Structured output tells the program how to interpret/use that information

    {
        "city": "Delhi"
    }

    That's why structured output becomes useful in agentic workflows.


The main reason is when we were getting the information from the LLM. That information was not in the structured form. Due to this we were not able to do many things like Storing the data into the database, APIs, etc.
That's why we require Structured output

- Ways to get structured Output
Structured output means getting the LLM's response in a predefined, structured format so that the application can easily process the data.

There are two particular ways to get the structured output:
    (i) with_structured_output()
    (ii) Output Parsers

Some models supports with_structured_output() and while those who don't than we use the Output Parsers concept. But the modern way is to use the first method

(i) with_structured_output()
with_structured_output() is used to make the model return the response according to a predefined schema/structure.
    LLM
    ↓
    with_structured_output()
    ↓
    Structured Data

It is generally used when the underlying model/provider supports structured output.

(ii) Output Parsers
An Output Parser processes the response generated by the LLM and converts it into the required format.

    LLM
    ↓
    Output Parser
    ↓
    Structured Data

For example:    
    parser = StrOutputParser()
    response = llm.invoke(prompt)
    result = parser.invoke(response)

- How to use with_structured_output()
with_structured_output()
        │
        ├── (i) TypedDict
        ├── (ii) Pydantic
        └── (iii) JSON Schema
(i) TypedDict
Defines the expected keys and their types using Python's TypedDict.

(ii) Pydantic
Defines the structure using a Pydantic BaseModel.
Advantage: It provides validation and gives you a structured Python object.

(iii) JSON Schema
Defines the expected structure using a JSON Schema dictionary.
Advantage: Useful when the schema needs to be represented in a standard JSON-based format.

# TypedDict
It is a way to define the dictionary in python where you specify what keys and values should exist. It helps ensure that your dictionary follows a specific structure

- Why not dictionary?
A normal dictionary only stores data, whereas TypedDict defines the expected keys and their data types, providing a clear structure/schema for the output.
For example:-
    Suppose you and your teammate are working on a project and you have data like this:
        person = {
            "name" : "Amandeep",
            "age" : 21
        }
    The other person can might treat the age data as string. To avoid these things we use TypedDict.

class Person:
    name : str
    age : int

But if we pass age = "24", it would still run. Because TypedDict doesn't necessarily enforced the data type. There is no validation at the runtime if we are using TypedDict(while Pydantic allows validation).


For example:
class Review(TypedDict):
    summary : str
    sentiment : str

structured_model = llm.with_structured_output(Review)

result = structured_model.invoke(
    "The hardware is great, but the software feels bloated. There are too many pre-installed apps that I can't remove. Also, the UI looks outdated compared to other brands. Hoping for a software update to fix this"
)

print(result)
print(result['summary'])
print(result['sentiment'])

Its not magically happening that we are getting the output in a strcutured way.
Behind the scenes -> The llm itself is sending the prompt like this:
    You are an AI assistant that extracts structured insights from text. Given a product review, extract:
        - Summary: A brief overview of the main points.
        - Sentiment: Overall tone of the review (positive, neutral, or negative).
    Return the response in JSON format.
