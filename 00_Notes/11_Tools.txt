# Tools in LangChain

A tool is just a Python function (or API) that is packaged in a way the LLM can understand and call when needed.

For example:-

```python
def multiply(a,b):
    return a x b
```

A human can call this function directly, but an LLM doesn't automatically know how to execute it.

LangChain makes this function available to the LLM as a Tool, with a name, description, and input schema.

---

## Why do we need Tools?

LLM(s) are great at:-

i) Reasoning → Understands questions and determines what information or action is needed.

ii) Language Generation → Generates explanations, summaries, and responses.

But an LLM cannot reliably do the following:-

- Access live data, such as current weather.
- Perform exact calculations.
- Call external APIs.
- Execute Python code or query a database.

For example:-

If you ask: What is the current weather of Haridwar?

The LLM may know general facts about Haridwar,

but it doesn't automatically have access to live weather data.

# Types of Tools in LangChain

There are two types of tools:-
1. Built-in tools
2. Custom Tools

## (i) Built-in Tools

Prebuilt tools provided by LangChain integrations or external libraries that can be directly used to perform specific tasks.

(a) Search Tool → Searches the web for information.

(b) Wikipedia Tool → Retrieves information from Wikipedia.

(c) Python REPL → Executes Python code.

(d) SQL Tool → Executes SQL queries on a database.

## (ii) Custom Tools

Tools created by developers using their own Python functions, APIs, or business logic to perform specific tasks.

For example:- Creating a tool to calculate the square of a number.

From langchain_core.tools import tool

@tool
def square(number: int) -> int:
    """Calculate the square of a number."""
    return number ** 2

square.invoke({
    "number": 25
})

# How Tools fit into the Agent Ecosystem

An AI agent is an LLM-powered system that can autonomously decide what actions to take and use external tools or APIs to achieve a goal.

→ LLMs understand the user request.

→ Agent decides what to do.

→ Tools perform the required actions.

→ Agent uses the results to produce the final answer.

There are two components of an Agent:-

## (i) Reasoning and Decision making:

LLM decide which action is required.

## (ii) Action

Tools execute the selected operation.

| AI agent (LLM + decision making) | Tools |
|---|---|
| Reasoning & Decision making | Action |
| LLM decide which action req: | Tools execute the selected oper. |

# Custom Tools

A custom tool is a tool that you define yourself.

## Use them when:
(i) You want to call your own APIs.
(ii) You want to encapsulate business logic.
(iii) You want the LLM to interact with your database, product or app.

There are three ways to create a custom tool:
(i) Using @tool decorator
(ii) Using StructuredTool and Pydantic
(iii) Using BaseTool class

## Using @tool decorator

Step 1 → Create a function  
Step 2 → Add type hints  
Step 3 → Add Tool (@) decorator

from langchain_core.tools import tool

@tool
def multiply(a: int, b: int) -> int:
    """Multiply two numbers."""

    return a * b

# It is not compulsory to give description but it is highly recommended.

# @tool → It is used to turn a function into a tool that the AI can see.

result = multiply.invoke({
    "a": 5,
    "b": 5
})

## Using Structured Tool and Pydantic (more strict way)

→ Pydantic: A Python library used to define data schemas and validate inputs.

- BaseModel → defines the input schema.
- Field → specifies description and validation rules.

→ Structured Tool: Converts a Python function into a LangChain tool with structured inputs.

from pydantic import BaseModel, Field
from langchain_core.tools import StructuredTool

class AddInput(BaseModel):
    a: int = Field(required=True, description="The first no. to add")
    b: int = Field(required=True, description="The second no. to add")

def add_func(a: int, b: int) -> int:
    return a + b

add_tool = StructuredTool.from_function(
    func=add_func,
    name="addition",
    description="Add 2 numbers",
    args_schema=AddInput
)

## Using BaseTool class

It is the abstract base class for all tools in LangChain.

It defines the core structure and interface that any tool must follow, whether it's a simple one-line or a fully customized function.

- All other tools like @tool, StructuredTool are built on top of BaseTool.

from langchain_core.tools import BaseTool
from typing import Type

class MultiplyInput(BaseModel):
    a: int = Field(..., description="First number")
    b: int = Field(..., description="Second number")

class MultiplyTool(BaseTool):
    name: str = "multiply"  # name of tool
    description: str = "Multiply two nos"
    args_schema: Type[BaseModel] = MultiplyInput

    def _run(self, a: int, b: int) -> int:
        return a * b

multiply_tool = MultiplyTool()  # create object

result = multiply_tool.invoke({
    "a": 5,
    "b": 5
})

## Toolkits

A toolkit is just a collection (bundle) of related tools that serve a common purpose — packaged together for convenience and reusability.

In LangChain:

A toolkit might be:
- Google Drive Toolkit
- And it can contain the following tools:

    → Google Drive Create File Tool: Upload file
    → Google Drive Search Tool: Search file
    → GoogleDrive Read File Tool: Read contents of file

from langchain_core.tools import tool

@tool
def add() -> int:
    pass

@tool
def multiply() -> int:
    pass

class MathToolkit:
    # name of your toolkit

    def get_tools(self):
        return [add, multiply]

toolkit = MathToolkit()  # create object and then you can use it

tools = toolkit.get_tools()  # print list of tools that you have created
