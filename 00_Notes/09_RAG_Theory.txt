## (i) Unable to access private data →

Suppose you have a company private information.

A general pre-trained LLM doesn't automatically know this information.

Because the data was:

→ not part of its original training data.

## (ii) Unable to give recent information →

A model learns from data available during its training:

for example:-

Training data
↓
2024
↓
LLM trained

Then something happens in 2025 and 2026.

The model wasn't trained on those events.

## (iii) Hallucinations →

An LLM doesn't always "know" whether a generated statement is actually true.

It generate text based on patterns it learned.

Sometimes it produces an answer that sounds correct but is actually incorrect.

for example:-

Question: Who invented xyz technology?

The model might answer:

> "xyz techn. was invented by John Smith in 1987".

But maybe John Smith never invented it.

That's a hallucination:

These problems can be solved by FINE TUNING upto an extent:-

## How FINE TUNING helps:-

> teach the model additional knowledge but it doesn't guarantee perfect accuracy.

### (i) Private data →

Fine tune the model on private/domain-specific data → model becomes familiar with that info, but it may not remember everything accurately.

### (ii) Recent information →

Fine tune the model on newer data → model can learn updated information, but frequent updates require repeated fine tuning.

### (iii) Hallucinations →

Fine tune the model using high quality, correct examples → can reduce certain hallucinations, but cannot completely eliminate them.


# Methods to adapt a pre-trained LLM →

After a model is pre-trained, we can further train it to improve its knowledge, task performance, or behaviour.

There are three methods:- (many more also)

- Supervised Fine tuning (SFT)
- Continued pre training
- RLHF (Reinforcement learning through human feedback)

## (i) Supervised Fine-Tuning (SFT) →

In this, we train the model using labelled data containing a prompt input and the desired output.

Pre trained model
↓
Labelled dataset
(prompt → desired o/p)
↓
SFT
↓
Adapted model

## (ii) Continued Pre training →

Unlike SFT, the data does not necessarily need labelled input-output pairs.

Pre-trained model
↓
Additional unlabeled data
↓
Continued pre-training
↓
Adapted model

## (iii) RLHF (Reinforcement learning from human feedback) →

Here, humans provide feedback about the model's responses, and this feedback is used to improve the model's behavior.

Pre-trained model
↓
Model response
↓
Human feedback
↓
Reinforcement learning
↓
Better - aligned model

## Steps:- (Supervised FT)

(i) Collect data

A few hundred - few hundred - thousand carefully curated examples (prompts → desired outputs)

(ii) Choose a method

Full-parameter FT, LoRA / QLoRA, or parameter-efficient adapters.

(iii) Train for a few epochs

You keep the base weights frozen or partially frozen and update only a small subset (LoRA) or all weights (full FT)

(iv) Evaluate and safety test

Measure exact match, factuality, and hallucination rate against held out data; red team for safety.

# In-Context Learning (ICL) →

It means giving the model instructions or examples inside the prompt so that it can understand what you want and perform the task without changing its parameters or training the model.

Pre-trained LLM
↓
Prompt + Examples
↓
Response

The model is not being trained. It is simply using the information provided in the current context to generate the answer.

→

For example:-

Input :- I love this movie  
Output :- Positive

Input :- This movie was terrible.  
Output :- Negative

Input :- The movie was amazing.  
Output :- [unclear]

The model sees the examples and understand the pattern.

Input → Sentiment

It can then generate → POSITIVE

(i) No training cost.

(ii) No specialized training expertise.

(iii) Flexible

(iv) Easy to experiment

# Types of In-context learning

There are three important forms:-

(i) Zero shot →

Give only instructions, no examples.

For example:-

Classify this review as Positive or Negative:

"I love this product".

---

(ii) One shot →

Give one example.

For example:-

"I love this product." → Positive

Now classify:-

"This product is terrible."

---

(iii) Few-shot →

Give multiple examples.

For example:-

"I love this product." → Positive

"This is terrible." → Negative

"The product is amazing." → Positive

Now classify:-

"The product is okay."

The model learns the pattern from the examples in the prompt.

# Understanding RAG architecture →

There are 4 core phases of RAG:-

## (i) Indexing (The prep work)

- Load: Read the file (e.g. PDF)
- Chunk: Cut text into small paragraphs (Text splitter)
- Embeddings: Convert chunks into no's/vectors
- Store: Save vectors in a database (vector store).

## (ii) Retrieval (The search)

When a user asks a question, convert the question to a vector and find the top 2-3 matching chunks in the DB.

## (iii) Augmentation (The prompt assembly)

Paste those matching chunks directly into a prompt template alongside with the user's question.

## (iv) Generation (The final answer)

Pass the combined prompt to the LLM so, it generates an answer based only on your retrieved data.

# Retrieval →

Retrieval is the real-time process of finding the most relevant pieces of information from a pre-built index (created during indexing) based on the user's question.

## (i) Step 1 - User gives a query →

The user asks a question.

The query is sent to the retriever.

## (ii) Step 2 - Convert query into an embedding →

The query is converted into a vector using the embedding model.

```text
Query
↓
Embedding model
↓
Query Embedding
INDEXING
Chunks → Embeddings → Vector Store
RETRIEVAL

(iii) Step 3 - Semantic Search →

Now, the query embedding is compared with the embeddings already stored in the vector store.

The system looks for vectors that are semantically similar to the query.

(iv) Step 4 - Return most relevant chunks →

The vector store returns the relevant chunks.

These becomes the CONTEXT.
