It is a workflow in which the next step depends on a condition or decision.

For example:

START
  ↓
Evaluate Essay
  ↓
Check Score
  ↙              ↘
Score >= 80      Score < 80
  ↓                ↓
Approve          Improve
Essay            Essay
  ↓                ↓
END              END

If we are adding a conditional edge then there must be a function.

## (i) Quadratic Equation Workflow

ax² + bx + c = 0

↳ Always 2 roots

→ First we find Discriminant: b² - 4ac = d

Type of roots depend upon the discriminant value.

### (a) d > 0
2 real roots

r1 = (-b + √d) / 2a

r2 = (-b - √d) / 2a

### (b) d = 0
(1 repeated root)

r1 = -b / 2a

### (c) d < 0
(no real roots)

## Workflow Diagram

START (a, b, c)
  ↓
Show Equation → ax² + bx + c
  ↓
Calculate Discriminant → b² - 4ac
  ├── d < 0 → No real roots ──────┐
  ├── d > 0 → Real roots ─────────┤
  └── d = 0 → Repeated roots ─────┤
                                   ↓
                                  END

## State

1. a (int)
2. b (int)
3. c (int)
4. equation (str)
5. discriminant (float)
6. final_result (str)

## Conditional Function

def check_condition(state: QuadraticState) -> Literal["no_real_roots", "real_roots", "repeated_roots"]:
    if state["discriminant"] < 0:
        return "no_real_roots"
    elif state["discriminant"] > 0:
        return "real_roots"
    else:
        return "repeated_roots"

This will redirect to the conditional edge.

## Graph

graph = StateGraph(QuadraticState)

graph.add_conditional_edges("calc_discriminant", check_condition)

Here the "edge_name" would be returned and it will execute the node.

graph.add_edge("no_real_roots", END)
graph.add_edge("real_roots", END)
graph.add_edge("repeated_roots", END)

# LLM-Based Review Handling Workflow

## 1. Overview

**Review → Find Sentiment → Conditional Routing**

- If the sentiment is positive, generate a positive response.
- If the sentiment is negative, run a diagnosis and generate an appropriate response.

## 2. State

The workflow maintains the following state fields:

1. `review`
2. `sentiment`
3. `diagnosis`
4. `final_response`

## 3. Workflow Diagram

```text
             START
               |
        find_sentiment
               |
        Conditional Edge
          /         \
      Negative     Positive
         |             |
   run_diagnosis   positive_response
         |
   negative_response
          \          /
              END
```

## 4. Structured Output Schemas

Two schemas are required for structured output.

### 4.1 Sentiment Schema

```python
class SentimentSchema(BaseModel):
    sentiment: Literal["positive", "negative"] = Field(
        description="Sentiment of review"
    )
```

### 4.2 Diagnosis Schema

```python
class DiagnosisSchema(BaseModel):
    issue_type: Literal[
        "UX", "Performance", "Bug", "Support", "Other"
    ] = Field(
        description="The category of issue mentioned in the review"
    )

    tone: Literal[
        "angry", "frustrated", "disappointed", "calm"
    ] = Field(
        description="The emotional tone expressed by the user"
    )

    urgency: Literal["low", "medium", "high"] = Field(
        description="How urgent or critical the issue appears to be"
    )
```

### 4.3 Review State

```python
class ReviewState(TypedDict):
    review: str
    sentiment: Literal["positive", "negative"]
    diagnosis: dict
    final_response: str
```

The returned value determines which conditional edge is executed.

## 6. Conditional Workflow

The workflow uses conditional routing to decide the next step.

```text
START
  |
find_sentiment
  |
  +---- Positive ----> positive_response ----> END
  |
  +---- Negative ----> run_diagnosis
                            |
                      negative_response
                            |
                           END
```

## 7. Key Concepts

- **Structured Output:** Ensures that the LLM returns data according to a predefined schema.
- **Pydantic:** Defines and validates structured output fields.
- **StateGraph:** Defines the workflow and its nodes.
- **Conditional Edges:** Determine the next node based on the output of a routing function.
- **Partial State Updates:** Nodes return only the state fields they update.
- **LLM-Based Diagnosis:** Extracts issue type, emotional tone, and urgency from negative reviews.
