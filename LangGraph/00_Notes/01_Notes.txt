# Introduction to Agentic AI

## A normal LLM call looks like this:

User prompt
↓
LLM generate response
↓
Final answer

## An agentic AI workflow can look like this:

User prompt
↓
LLM decides what action is needed
↓
Tool call (if required)
↓
Tool result returned to LLM
↓
Final answer

An agentic system can choose actions towards a goal and adapt what it does based on the situation or results.

Goal → Decide → Act → Evaluate → Decide Again

If the AI can select between different actions based on the situation, that is agentic behaviour.

**Definition:** Agentic AI is an AI that takes a goal, decides what actions to take, and works toward completing that goal with minimal human guidance.

## For example:

→ Generative AI

"Why might a data pipeline fail?"

The AI generates an explanation based on its knowledge.

→ Agentic AI

"Investigate why my data pipeline failed."

The AI might:
1. Examine the logs.
2. Decide what diagnostic to run.
3. Analyze the result.
4. Try another diagnostic (if required).

(Working towards a goal by choosing and adapting actions)

## Note

(i) Is a tool necessary for agentic AI? No

(ii) Can tools make an agent more capable? Yes

(iii) Does using a tool automatically make AI agentic? No

Agentic AI can work in a cycle, it observes results, decides what to do next, and continues investigating based on what it learns.

## Key Characteristics of Agentic AI

(i) Autonomous

(ii) Goal oriented

(iii) Planning

(iv) Reasoning

(v) Adaptability

(vi) Context awareness

## (i) Autonomy

Agentic AI can work towards a goal without requiring a human to tell it every single step.

- **Without autonomy**

  You tell the AI to inspect the logs, then tell it to check the logs, then tell it to check the databases, then tell it what to do next.

- **With autonomy**

  You gave it the goal, and it chooses the next step within the permissions and rules you have defined.

- **Autonomy can be controlled**

  Autonomy does not mean giving AI unlimited freedom.

  (i) Permission scope

  (ii) Human in the loop (HITL)

  Human approval is needed.

  (iii) Override controls.

  Human can interrupt or change what the AI is doing.

- **Autonomy can be dangerous**

  Imagine a recruitment AI that can act independently. If its rules or decisions are flawed, it might:

  (i) Send job offers with incorrect salary details.

  (ii) Unfairly shortlisting students.

Autonomy means the AI can act independently, but its permissions, decisions, and actions should be controlled appropriately.


## (ii) Goal Oriented

Being goal oriented means that the AI system operates with a persistent objective in mind and continuously directs its actions to achieve that objective, rather than just responding to isolated prompts.

→ Goals act as a compass for autonomy.

→ Goals can come with constraints. {SHMC backed engineer from Andhra only?}

→ Goals are stored in core memory.

→ Goals can be altered.

## (iii) Planning

Planning means breaking a big goal into smaller actions and choosing a suitable way to achieve it.

### Step 1 → Generate Multiple Plans

AI considers different ways to achieve the same goal.

Plan A → Post job on LinkedIn.

Plan B → Use employee referrals.

### Step 2 → Evaluate Each Plan

- Cost?
- Efficiency?
- Risk?
- Constraints?

### Step 3 → Select the Best Plan

AI chooses a plan based on evaluation.

**Two ways**

↓  

**Multiple plans**

AI considers alternatives (Plan A, Plan B).

**Strategic planning**

Execute the plan, examine the result and revise its plan (if necessary).

## (iv) Reasoning

It means analyzing information, connecting facts, and using them to reach a conclusion or make a decision.

**Planning**

↳ Decides what steps to take.

**Reasoning**

↳ Analyzes information to reach conclusions.

## (v) Adaptability

*Changing your approach based on new info*

It means the AI can change its approach when it receives new information or when its current approach doesn't work.

# Why LangGraph is Useful?

## Challenge 1: Control Flow Complexity

### (i) Challenges in Complex LangChain Workflows:

- Conditional branching: Choose paths based on conditions.
- Loops: Repeat steps until a condition is met.
- Jumps: Return to earlier steps or move to another step.

### (ii) How LangGraph Helps:

- Nodes: Perform tasks.
- Edges: Define the next step.
- State: Store information shared between steps.
- Less glue code: Extra code needed to connect different components.

LangGraph makes complex workflows easier to organize and manage.

---

## Challenge 2: Handling State

- **State:** A dictionary that stores the current information of a workflow as key-value pairs.
- **Purpose:** Keeps track of progress and shares information between workflow steps.

- **In LangChain:** Managing and updating shared information across a complex workflow may require extra glue code.
- **In LangGraph:** State is a core concept. A node reads the current state and returns updates to it.

LangGraph makes state management easier by providing a shared state that nodes can read and update.

---

## Challenge 3: Event-Driven Execution

Workflow

↓  
**Sequential (LangChain)**

**Event-Driven (LangGraph)**

### In LangChain:

In this, a chain executes completely without pauses, such as:

Prompt → LLM → Prompt → LLM

### In LangGraph:

Nodes can execute conditionally, loop back, or pause for human input.

**For example:**

Suppose we have created a hiring website. We have posted a JD and we want to stop the registration after 7 days.

---

## Challenge 4: Fault Tolerance

**Meaning:** To handle failures without losing all of its progress.

- **In LangChain:** If a step fails, you need to handle that error. In a long chain, managing failures and recovery across multiple steps is complicated.
- **In LangGraph:** Each task is a node connected to edges. You can configure retries, save checkpoints, and control what happens when a particular node fails.

---

## Challenge 5: Human in the Loop (HITL)

**Meaning:** A human reviews, approves, or provides input before an AI workflow continues.

- **In LangChain:** You generally need to build the human interaction and waiting mechanism into your application.
- **In LangGraph:** You can use interrupts to pause a workflow, wait for human input, and resume execution afterward.

LangGraph makes HITL easier to implement by allowing workflows to pause and resume while preserving state through checkpointing.

---

## Challenge 6: Nested Workflows

- **Meaning:** Breaking a large workflow into smaller, reusable workflows, each responsible for a specific task.

- **In LangChain:** You can combine chains, but coordinating complex workflows with their own state, branching, and loops can become difficult.

- **In LangGraph:** You can use subgraphs → graphs nested inside a larger graph → to organize complex workflows into manageable parts.

LangGraph subgraphs help organize complex workflows into smaller, reusable components that are easier to maintain and test.

## Challenge 7: Observability
- Meaning: The ability to monitor a workflow and understand what happens during its execution.
- In LangChain: You can use logging and tracing tools, but tracking complex workflows across multiple components may require extra setup.
- In LangGraph: You can inspect node execution, state updates, and workflow paths. Tools like LangSmith help trace and debug executions.
- Example: If an incident investigation produces an incorrect diagnosis, you can trace which node retrieved the evidence, what a diagnostic node returned, and where the workflow went wrong.
Key takeaway: Observability helps you understand, monitor, and debug an AI workflow by showing what happened at each step.

# Conclusion

## 1. What is LangGraph?

LangGraph is an orchestration framework that enables you to build **stateful, multi-step, and event-driven** workflows using large language models (LLMs). It's ideal for designing both single-agent and multi-agent agentic AI applications.

Think of LangGraph as a **flowchart engine for LLMs** — you define the steps (nodes), how they're connected (edges), and the logic that governs the transitions. LangGraph takes care of **state management, conditional branching, looping, pausing/resuming, and fault recovery** — features essential for building robust, production-grade AI systems.

## 2. When to Use What?

- Use **LangChain** when you're building **simple, linear workflows** — like a prompt chain, summarizer, or a basic retrieval system.

- Use **LangGraph** when your use case involves **complex, non-linear workflows** that need:
  - Conditional paths
  - Loops
  - Human-in-the-loop steps
  - Multi-agent coordination
  - Asynchronous or event-driven execution

## 3. Should We Still Use LangChain?

Yes. LangGraph is built on top of **LangChain** — it doesn't replace it.

You'll still use LangChain components like:

- `ChatOpenAI` (LLMs)
- `PromptTemplate`
- `Retrievers`
- `DocumentLoaders`
- `Tools`, etc.

LangGraph handles **workflow orchestration**, while LangChain provides the **building blocks** for each step in that workflow.

# LangGraph Core Concepts

## (i) LLM Workflows

Workflow → Series of tasks that are implemented to achieve a specific goal.

LLM Workflows → Series of tasks that use one or more LLM calls to achieve a goal.

- Each step in a workflow performs a distinct task, such as prompting, reasoning, tool calling, memory access or decision making.
- Workflows can be linear, parallel, branched or looped, allowing for complex behaviours like retries, multi-agent communication, or tool-augmented reasoning.

### Common Workflows

#### (i) Prompt Chaining

We talked multiple times to LLM in this workflow.

**Flow:**

Input → LLM Call 1 → Output 1 → Gate

Gate checks whether Output 1 satisfies a particular condition or not.

- **Pass:** Gate → LLM Call 2 → Output 2 → LLM Call 3 → Output
- **Fail:** Gate → Exit

### (ii) Routing

**Step 1: Input**
- The user provides a query.

**Step 2: LLM Call Router**
- The router analyzes the input and decides which path is appropriate.
- It directs the request to the selected LLM call.

**Step 3: Selected LLM Call**
- The chosen LLM processes the request.
- Different LLM calls may handle different tasks.

**Step 4: Output**
- The selected path produces the response.

**Flow:**

Input → LLM Call Router

- LLM Call 1 → Output
- LLM Call 2 → Output
- LLM Call 3 → Output
