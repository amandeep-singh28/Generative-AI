# Models

In LangChain, "models" are the core interfaces through which you interact with AI models.

## Why do we need LangChain for Models?

### 1. Directly Using OpenAI

OpenAI provides its own SDK/API to communicate with its models.

Current Python approach:

from openai import OpenAI

client = OpenAI()

response = client.responses.create(
    model="gpt-5.6",
    input="Write a one-sentence bedtime story about a unicorn."
)

print(response.output_text)


What happens?

Your Application
       ↓
OpenAI SDK
       ↓
OpenAI API
       ↓
GPT Model
       ↓
Response


### 2. Different Providers Have Different Implementations

Different LLM providers provide different SDKs and API structures.

For example:

OpenAI
client.responses.create(...)

Anthropic
client.messages.create(...)

Gemini
Gemini-specific API / SDK


Their:

- Methods can be different
- Parameters can be different
- Request formats can be different
- Response formats can be different

Therefore, if we directly use a provider's SDK and later switch providers, we may need to modify our application code.


### 3. LangChain's Solution

LangChain provides a common interface for interacting with different LLM providers.

Instead of directly depending on each provider's SDK:

Your Application
       ↓
Provider SDK
       ↓
LLM


We can use:

Your Application
       ↓
LangChain
       ↓
Common Model Interface
       ↓
OpenAI / Gemini / Anthropic


For example:

response = llm.invoke("Hello")

The underlying implementation can be different for OpenAI, Gemini, or Anthropic, but our application can interact with the model through a similar interface.


## Remember

Provider SDK → Provider-specific implementation

LangChain → Common interface for different LLM providers


### Main Idea

LangChain does not replace the LLM.

It provides an abstraction layer that makes it easier to build applications that interact with different LLM providers.


# Models in LangChain

There are mainly two types of models:

(i) Chat Models
(ii) Embedding Models

Chat models take messages as input and return messages.

While embedding models convert text into vectors representing semantic meaning.


# Chat Models

It is used when we want the AI to understand input and generate a response.

User
  ↓
"What is RAG?"
  ↓
Chat Model
  ↓
"RAG stands for Retrieval-Augmented Generation"

Example in LangChain include:

- ChatOpenAI
- ChatGoogleGenerativeAI
- ChatAnthropic
- ChatGroq

from dotenv import load_dotenv
from langchain_google_genai import ChatGoogleGenerativeAI

load_dotenv()

llm = ChatGoogleGenerativeAI(
    model="gemini-2.5-flash"
)

response = llm.invoke("Explain Generative AI in simple words")

print(response.content)


# Embedding Models

They convert text into a vector of numbers that represents its semantic meaning.

"ML is a subset of AI"
          ↓
    Embedding Model
          ↓
[0.21, -0.43, 0.87, 0.12, .....]

from dotenv import load_dotenv
from langchain_google_genai import GoogleGenerativeAIEmbeddings

load_dotenv()

embeddings = GoogleGenerativeAIEmbeddings(
    model="gemini-embedding-001"
)

vector = embeddings.embed_query(
    "What is Generative AI?"
)

print(vector)

# Model Parameters

## 1. Temperature

Temperature controls the randomness/creativity of the model's output.

For example:

temperature = 0

means the model behaves more deterministically.

Higher temperature:

More randomness
       ↓
More variation
       ↓
Potentially more creative responses

Lower temperature:

Less randomness
       ↓
More predictable responses

For tasks like:

- Factual answering
- Classification
- Structured extraction

we generally prefer lower randomness.

For:

- Brainstorming
- Creative writing
- Idea generation

we may want more variation.

### 🧠 Remember

Temperature = How random/creative?


## 2. max_output_tokens

max_output_tokens controls the maximum amount of output the model can generate.

For example:

max_output_tokens = 500

This does NOT mean:

"The model will always produce exactly 500 tokens."

It means:

"The model can generate up to the specified output limit."

### 🧠 Remember

max_output_tokens = How much output?


## 3. invoke() vs stream()

These are two ways to receive the model's response.

### invoke()

With invoke(), we wait for the model to generate the complete response.

Flow:

Request
   ↓
[Model generates]
   ↓
Complete response

Example:

response = model.invoke(
    "Explain Generative AI in simple words."
)

print(response.content)


### stream()

With stream(), the response is received incrementally in chunks as it is generated.

Flow:

Request
   ↓
"Generative"
   ↓
" AI"
   ↓
" is"
   ↓
" a"
   ↓
" branch"
   ↓
...


Example:

for chunk in model.stream(
    "Explain Generative AI in simple words."
):
    print(chunk.content, end="")


Streaming is useful for:

- ChatGPT-style interfaces
- Real-time chat
- Streaming UI

### 🧠 Remember

invoke()
    ↓
Complete response

stream()
    ↓
Response arrives incrementally


# 🔥 Quick Memory Trick

temperature
    ↓
HOW RANDOM / CREATIVE?

max_output_tokens
    ↓
HOW MUCH OUTPUT?

invoke()
    ↓
GIVE ME THE COMPLETE RESPONSE

stream()
    ↓
GIVE ME THE RESPONSE AS IT IS GENERATED

# Prompts (2nd Component)

A prompt is an instruction or input that you give to an LLM so it knows what task to perform.

User / Application
       ↓
    Prompt
       ↓
      LLM
       ↓
   Response


# Classification of Prompts

Prompts
   │
   ├── Single Message Prompts
   │       │
   │       ├── (i) Static Prompts
   │       │
   │       └── (ii) Dynamic Prompts
   │
   └── Multi Message Prompts
           │
           ├── (i) Messages (Manual)
           │       │
           │       ├── System
           │       ├── Human
           │       └── AI
           │
           └── (ii) Chat
                   │
                   └── Chat Prompt Template

# Single Message Prompts

A single message prompt means we're essentially working with one prompt/input sent to the model.

## (i) Static Prompts

A static prompt means we're working with one prompt/instruction that remains constant.

The instructions given to the LLM remain constant every time the application runs.

### Example

You are a college research assistant.

Your responsibilities are:

- Answer questions about college.
- Provide information about admission.
- Provide information about fees.
- Provide information about placement.
- Provide information about scholarships.

The instruction doesn't change.


## Why Static Prompts?

When we want the LLM to have a specific responsibility.

LLM
  ↕
Fixed Instructions
  ↕
College Assistant

The static prompt establishes the behaviour and scope of the application.

If question → College related
        ↓
      Answer

If question → Unrelated
        ↓
"I am a college research assistant..."


## Note

Static does not mean that the entire input to the LLM never changes.

The instruction / prompt template is static.

The user's query can still change.

"The user input can change.

The static part refers to the fixed instruction provided to the model."
